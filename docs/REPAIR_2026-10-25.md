# ผลซ่อม workflow และทดสอบจริง 25 ตุลาคม 2026

## สาเหตุและการแก้

Production Webhook ตอบ HTTP 500 `Error in workflow` เพราะ Code node **ตรวจข้อมูลและคำนวณแผน** ใช้ชื่อ node ภาษาอังกฤษผ่านฟังก์ชัน `rows(name)` ขณะที่ชื่อ node จริงเป็นภาษาไทยแล้ว

แก้การอ้างอิง `Read products`, `Read inventory`, `Read policies`, `Read requests` ให้ตรงกับ **อ่านข้อมูลสินค้า**, **อ่านข้อมูลสต็อก**, **อ่านเกณฑ์เติมสินค้า**, **อ่านใบเสนอเดิม** ใน workflow เดิมบน n8n Cloud โดยคง Google credential, spreadsheet และ Header Auth เดิมไว้ ตรวจแล้วว่าขั้นเตรียมแถว เงื่อนไขเพิ่ม/แก้ และอ่านกลับอ้างชื่อ **ตรวจข้อมูลและคำนวณแผน** ถูกต้อง

เผยแพร่เวอร์ชัน **แก้ชื่ออ้างอิงภาษาไทย 25-10-2026** สำเร็จ และปรับตัวสร้าง workflow ในโปรเจกต์ให้สร้างชื่อไทยกับจุดอ้างอิงที่ตรงกัน รวมคำอธิบาย node ภาษาไทย

## ผลตรวจที่ทำจริง

- Production `list` และ `evaluate` กลับมา HTTP 200, `ok: true`
- หน้าเว็บแสดงสินค้า 82 รายการ: ควรเสนอเติม 28, เพียงพอ 49, รอตรวจ 5
- ตรวจโครงสร้าง workflow การเชื่อมต่อ และชื่อที่ Code node อ้างอิง: ผ่าน
- Unit tests: 33/33 ผ่าน
- Integration ผ่าน n8n Cloud + Google Sheets: 14/14 ผ่าน รวมสร้าง อ่าน แก้ ป้องกันการส่งซ้ำ ปฏิเสธ revision เก่า ยกเลิก และปฏิเสธคำขอไม่มี Header Auth
- กดผ่านหน้าเว็บจริง สร้าง SKU-0011 จำนวน 21 ชิ้น จากนั้นเปิดรายการ แก้เป็น 20 ชิ้นและรอตรวจ บันทึกสำเร็จ
- อ่านแท็บ `requests` ใน Google Sheets โดยตรง พบจำนวน 20, สถานะ `submitted`, revision 2 ตรงกับเว็บ
- ยกเลิกรายการทดสอบผ่านเว็บแล้ว อ่านยืนยันเป็น `cancelled`, revision 3 และไม่มีใบเสนอทดสอบ SKU-0011 ที่ค้างใช้งาน
